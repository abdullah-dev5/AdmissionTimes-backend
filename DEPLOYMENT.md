# Deploying AdmissionTimes

| Part | Host | Config in repo |
|---|---|---|
| API (this repo) | Render, free web service | `render.yaml` |
| Web app | Vercel, free (Hobby) | `admission-times-frontend/vercel.json` |
| Database, auth, realtime | Supabase (existing project) | `supabase/migrations` |
| Scheduled jobs on time | cron-job.org (free) | calls `/api/v1/internal/jobs/*` |
| Scrapers | GitHub Actions (existing workflow) | `AdmissionTimes-Scrapers/.github/workflows/scraper.yml` |
| Mobile app | Expo EAS build | `AdmissionTimes-MobileApp/eas.json`, `app.config.js` |

Order matters: deploy the API first, because the web app, the mobile app and the scrapers all need its URL.

## Before you start

1. **Brevo:** Security → Authorized IPs → turn the restriction **off** (or SMTP fails with `525 5.7.1 Unauthorized IP address`). Render's outgoing IPs change.
2. **Merge** the open PRs into `main` in every repo. Render and Vercel deploy `main`.
3. Have the current backend `.env` at hand: the secret values are copied from it.

## 1. API on Render

1. Render → **New → Blueprint** → connect GitHub → pick `AdmissionTimes-backend`. Render reads `render.yaml`.
2. Render asks for every `sync: false` value. Copy them from `.env`, except:
   - `CORS_ORIGIN` and `WEB_APP_URL`: the Vercel URL. You don't have it yet, so enter `https://placeholder.vercel.app` and update both after step 2 (no trailing slash).
   - `EMAIL_FROM`: a sender verified in Brevo, e.g. `AdmissionTimes <no-reply@yourdomain>`.
   - `CRON_SECRET` is generated by Render. You need it in step 3.
3. **Deploy.** The build runs `pnpm install` and `pnpm build`, then the service starts with `pnpm start`.
4. Check that `https://<service>.onrender.com/health` returns `"status": "ok"`. The default service name gives `https://admissiontimes-api.onrender.com`.

If the start fails with `Missing required environment variables`, the log lists them. Production refuses to start without `CORS_ORIGIN`, the Supabase keys, and `WEB_APP_URL` (when email is on).

## 2. Web app on Vercel

1. Vercel → **Add New → Project** → import `admission-times-frontend`. Framework, build command and output folder come from `vercel.json`.
2. **Environment variables** (Production):

   | Name | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://admissiontimes-api.onrender.com/api/v1` |
   | `VITE_SUPABASE_URL` | same as the backend `SUPABASE_URL` |
   | `VITE_SUPABASE_ANON_KEY` | the Supabase anon/publishable key (never the service role key) |
   | `VITE_ENABLE_REALTIME` | `true` |
   | `VITE_APP_UTC_OFFSET` | `+05:00` |
   | `VITE_API_TIMEOUT_MS` | `60000` (a sleeping Render service needs up to a minute to wake) |

   `VITE_*` values are compiled into the build, so **redeploy** after changing any of them.
3. Deploy, then copy the production URL (e.g. `https://admissiontimes.vercel.app`).
4. Back in Render, set `CORS_ORIGIN` and `WEB_APP_URL` to that URL and save (Render redeploys).
5. **Supabase** → Authentication → URL Configuration:
   - Site URL: the Vercel URL.
   - Redirect URLs: add `https://<vercel-url>/reset-password` and `https://<vercel-url>/signin`.

   Without these, password-reset and sign-up confirmation emails link to localhost.

`vercel.json` rewrites every path to `index.html`, so refreshing or opening a deep link (`/student/search`) works instead of returning Vercel's 404.

## 3. Keep the API awake and jobs on time (cron-job.org)

A free Render service sleeps after 15 minutes without requests, and in-process timers stop while it sleeps. Create a free cron-job.org account and add:

| Job | URL | Method | Schedule | Header |
|---|---|---|---|---|
| Keep-alive | `https://<api>/health` | GET | every 10 minutes | none |
| Deadline reminders | `https://<api>/api/v1/internal/jobs/reminders` | POST | every hour, minute 5 | `x-internal-service-token: <CRON_SECRET>` |
| Email retries | `https://<api>/api/v1/internal/jobs/email-retries` | POST | every 15 minutes | same header |
| Recommendations | `https://<api>/api/v1/internal/jobs/recommendations` | POST | daily, 02:00 | same header |

Each job answers `202` at once and keeps running. Jobs never overlap, and reminders are sent once per program and threshold however often they run. `GET /api/v1/internal/jobs` (same header) shows each job's last run.

## 4. Scrapers (GitHub Actions)

In `AdmissionTimes-Scrapers` → Settings → Secrets and variables → Actions:

- `BACKEND_BASE_URL` = `https://admissiontimes-api.onrender.com`
- `SCRAPER_INTERNAL_SERVICE_TOKEN` = the same value as in Render
- Keep `SCRAPER_API_KEY` and `GEMINI_API_KEY`. `DATABASE_URL` (the history mirror) is optional.

Run the workflow once by hand (Actions → Run workflow). The admin **Scraper Monitor** then shows the run. A real run replaces demo deadlines with the universities' real dates.

## 5. Mobile app (EAS)

`eas.json` sets `API_BASE_URL` for the `preview` and `production` profiles. Change it there if your Render URL differs. Then:

```bash
npx eas build --profile preview --platform android   # installable APK for testing
```

For local development against the deployed API: `API_BASE_URL=https://<api>/api/v1 npx expo start`.

## After deploying

- Sign in as each role on the Vercel URL (admin, university, student).
- Trigger a reminder run (`POST .../internal/jobs/reminders`). In the admin Email Delivery Logs, confirm a `sent` row.
- The free Render plan has no persistent disk. Uploaded PDFs are processed in memory and nothing is stored locally, so restarts lose nothing.
